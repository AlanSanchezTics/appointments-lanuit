## Feature context

The goal of this feature is to introduce application-wide internationalization so the product can support multiple languages in a maintainable and scalable way.

## Desired feature

- Implement the business logic required to detect the device language and use it to display the application in that language.

## Source of truth for translated user-facing messages

The frontend is the **single owner of localized user-facing text**.

The agent must assume the following:

- The backend must **not** return localized human-readable strings intended for final display.
- The backend must return **stable message codes / translation keys / structured error identifiers** that the frontend can translate.
- The frontend must resolve those codes or keys into localized strings using `i18next` / `react-i18next`.
- Any existing backend behavior that returns user-facing strings directly must be identified and evaluated for refactor.
- If a backend response includes dynamic values, the plan must describe how those values are returned separately so the frontend can interpolate them safely into translated messages.
- The internationalization strategy must avoid duplicating translation ownership across frontend and backend.
